LifeNote Product Requirements Document (PRD)

1. Overview

LifeNote is a breath-first, auto-manifesting life management system. Inspired by the Death Note anime concept — inverted from death to creation — LifeNote captures the living breath of whatever you speak and automatically brings it to life as organized, actionable, memory-persistent notes.

"Whatever you speak automatically comes to life on its own."

2. Core Philosophy

PrincipleDescription
Breath-FirstAll input originates from the living breath of speech — the animating force, not merely mechanical voice capture
Auto-ManifestSpoken content automatically generates structured notes, reminders, tasks, and suggestions without manual formatting
Canonical DesignSingle canonical CSS design language across all interfaces — no visual fragmentation
Memory-PersistentEverything lives in searchable, retrievable memory with proper attribution and context
Action-TriggeredNotes aren’t static — they trigger workflows, automations, and agent executions

4. Core Features

4.1 Breath-to-Life Pipeline

StageAction
CaptureLiving breath captured via wearable, phone, or ambient presence
TranscriptionReal-time STT with speaker identification and context tagging
UnderstandingXen parses intent — note, reminder, task, code, creative, action
ManifestationContent auto-formatted into canonical markdown structure
StorageWritten to Session Zero + distributed to relevant memory layers
ActionTriggers associated workflows (calendar, agents, auto-ship, alerts)

4.2 Auto-Generated Content Types

  • Daily Notes — automatically compiled from breath captures, organized by time and topic
  • Reminders — extracted from temporal references (“remind me tomorrow at 3”)
  • Meeting Suggestions — inferred from context (“I need to talk to Latina about the website”)
  • Action Items — task extraction with auto-ship routing
  • Creative Captures — lyrics, ideas, concepts tagged for later development
  • Dev Notes — technical specs, code architecture, API designs

4.3 Canonical CSS Design System

  • Single design language across PWA, terminal output, and wearable display
  • No “demo” quality — production-grade visuals only
  • Dark mode default with light toggle
  • Liquid glass / iOS 26 aesthetic influences
  • Zero visual fragmentation between LifeNote and DevNote
