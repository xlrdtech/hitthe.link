1. The product in one sentence

One brain watches every surface qi can be reached on, scopes each thread without being told, acts on what it is allowed to act on, brings him only what actually needs him — and proves every claim against a real artifact instead of a status code.

2. Non-negotiables (violating any one of these means it is not the product)

#RuleWhy it exists
N1One consumer. Not one agent per thread. Scopes are DATA, not running processes.Two listeners on one thread both answer. From qi's own omni-router-spec.
N2Never ask him to check. Surfacing is push, never pull.His standing law. Muted means no auto-reply, never no auto-surface.
N3No confirmation steps. HOTL — human out of the loop, not in it."I hate it, actually." Any tap/click/confirm = failure.
N4All threads literally. Every surface, every inbox, ≥300 threads.The proof-of-concept bar he set.

3. Architecture — six stages, one process

  INGEST ──► SCOPE ──► DECIDE ──► ACT ──► VERIFY ──► SURFACE
    │          │          │         │        │           │
 every      754        mode:     reply /  read the    one line
 surface   scopes     active    trigger /  artifact    per person,
 one poll  663 bound  muted     digest /   back        gist only,
           threads    auto      log        (N5)        7pm-7am
                      digest

INGEST — xen-omni-router, one persistent process, launchd com.xen.omni-router, KeepAlive, 5s cycle. Deep 40-page backfill on boot (800 messages), then a 3-page tail. Says "BACKFILL TRUNCATED… older history exists and was NOT read" exactly once rather than crying wolf every cycle. Publishes every inbound to omni.event over NATS via raw socket — no CLI dependency to be missing.

SCOPE — registry-bound first (curated wins), then qi's own autoscope_rules. Ground truth over guessing: isReadOnly from the platform decides "does not accept replies," not a name-matching regex.

DECIDE — four modes. active = auto-execute per playbook. muted = ingested, logged, scoped, still surfaced (N2). auto = sole-member trigger-channel, any inbound fires its workflow. digest = new, qi decree: senders that do not accept replies get harvested for topics, never answered.

ACT — replies go out on the real surface. Money, credentials, OAuth, and other people's customers never auto-execute (§6).

VERIFY — every send read back via /v1/messages/search; every spoken line proved by a unique marker in the send log.

SURFACE — one line per person, names and counts only, never the transcript. Bots, closed loops, and threads where qi spoke last are filtered out. 7pm–7am window, ≥15min apart, once per person until they say something new.

5. Testers via OmniRoute (qi's phrasing, built to it)

Two kinds of independence, and xen-tester is explicit about which it has:

  1. Independent method — always on. Every test exercises the real path and asserts on

a real artifact. Never an exit code (VVS backgrounds its SMS leg and always exits 0), never a cached field (get_chat.lastActivity lags and caused a duplicate message to a real person), never a file size (the send log crossed 10 MiB with three log-cap daemons running), never a ping (nitro11.xlrd.org resolves to Cloudflare and answers in 4ms while the host has been offline 28 days).

  1. Independent judge — --via-omniroute. Routes the evidence through

localhost:20128/v1 so a different model rules on whether the claims are supported. Blocked: the gateway holds zero provider keys. When asked to judge with no keys it reports CANNOT JUDGE EXTERNALLY and exits 2. It does not fall back to self-grading, because that is the exact thing qi ruled out.

6. The HOTL boundary — what runs itself vs what is his alone

Auto-executes, no confirmation (N3): replying to his own friends, family and customers; scoping; surfacing; reminders; digesting non-repliable content; logging.

Never auto-executes — not a confirmation step, a hard boundary:

  • Money. Sending, moving, or committing funds. The $10 to $big3atl sat because only

he can send it.

  • Credentials. No typing passwords into forms, no granting OAuth, no minting App

Passwords, no opening the quarantined plaintext-credential file.

  • Other companies' customers. ELISID/RingCentral/Beetexting go to Anthony for

approval. "The only exception is if it's somebody else's platform."

  • Network exposure changes. tailscale funnel off is his call — that URL may be how

his phone reaches the UI.

  • Known scams. [redacted phone number] never gets a reply.

9. What went wrong building it, so it is not repeated

Four proxies produced four false results in one night, and two caused user-visible harm — a duplicate message to ADMIN EARTH (retried on a false negative) and a false P0 claiming VVS was dead when every send had returned http 200. The general rule is now canon in the vault: before trusting a signal, ask what else could move this reading while the fact stays the same. If the answer is another process, a cache, or a background job — it is a proxy. Go get the artifact.
