PRD — AI-Native E2E Test & Debug Harness: Stagehand × Browserbase × OmniRoute

Owner: qi · Built by: Xen · Written: 2026-08-01 03:20 EDT Status: grounded (deps installed, verified) → building the proof harness

qi's framing, verbatim, this night:

"i dont trust your judgment on verifying completion. whats the best tool for end to end thorough testing and debugging" · "and testers via omniroute" · "I heard it's best to not have you test yourself." · "Test like a real human user." · "the one with stagehand browserbase and omniroute" · "i insist on that PRD"

1. The product in one sentence

A test harness that drives the REAL product like a human — through a real browser — and lets a DIFFERENT model (not Xen, routed via OmniRoute) rule on whether it worked, proving every verdict against a captured artifact (screenshot / recording / extracted DOM), never a status code.

This is the concrete answer to the night's three demands at once:

  • C32 "test like a real human user" → Stagehand performs real act() on the live UI.
  • N8 "Xen does not grade Xen" → the judging LLM is served by OmniRoute = a model that is not this session.
  • N5/C17 "verify the thing, not a proxy" → the artifact is a Browserbase session recording + screenshot, inspectable without Xen.

3. Architecture

  SPEC (plain English steps)
      │
      ▼
  Stagehand ──act/extract──► real browser ──► REAL surface (tui.xlrd.org, Beeper UI, any glass)
      │                          │
      │ LLM calls                └─► ARTIFACT: screenshot + Browserbase recording + extracted DOM
      ▼
  OmniRoute :20128/v1  ──► a model that is NOT this Xen session  ──► VERDICT (pass/fail + why)
      │
      ▼
  xen-tester --via-stagehand  ──► exit 0/1/2 (2 = cannot-tell), artifact path logged
  • Local mode (default, $0): Stagehand drives local Chromium. No Browserbase key needed. Proves the harness today.
  • Cloud mode (opt-in): set BROWSERBASE_API_KEY + BROWSERBASE_PROJECT_ID → sessions run in Browserbase with recordings. This is the one qi-gated cred (§6).
  • LLM: modelClientOptions.baseURL = http://127.0.0.1:20128/v1. Independent judge satisfied when OmniRoute holds ≥1 provider key (else the harness reports CANNOT-JUDGE and exits 2 — never self-grades).

5. Acceptance criteria (artifact-backed, per N5)

  1. Harness opens a REAL surface and returns an extracted fact from the live DOM. (artifact: the fact)
  2. A screenshot of that surface is written to disk and is non-empty. (artifact: the PNG)
  3. Stagehand's LLM calls resolve through OmniRoute :20128, not an Anthropic key of this session. (artifact: OmniRoute access log / a completion)
  4. On a deliberately-wrong assertion, the harness exits 1 (fails honestly), not 0.
  5. With OmniRoute holding no provider key, the judge lane reports CANNOT-JUDGE and exits 2 — never self-grades (N8).
  6. Cloud mode produces a Browserbase session recording URL. (blocked until §6 key)

6. The one gated cred (do NOT auto-provision)

  • Browserbase API key + project id — qi's to add (free tier exists). Until then the harness runs LOCAL and every other acceptance criterion is still provable. This is the only blocker, and it blocks ONLY the cloud-recording upgrade, not the harness itself.
  • OmniRoute provider keys (for the independent-judge lane) — already a tracked qi blocker (omniroute-keys loop). The harness degrades to CANNOT-JUDGE without them, exactly as N8 requires.

7. How this closes the night's actual question

qi asked "best tool for end-to-end thorough testing and debugging" and disagreed with a bare "Playwright." The honest, complete answer is this stack: Playwright is the engine, Stagehand is the human-like driver on top, Browserbase is the artifact + scale, OmniRoute is the independent judge. Playwright alone tests the glass with brittle selectors and no independent grader; this harness tests the glass like a person AND has a different model sign off — which is the part qi actually cares about.
