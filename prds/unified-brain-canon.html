qi 2026-06-24 injected a full research doc (Memory-System-and-Routing-Research.md). This is the architecture overhaul for memory + agent dispatch. Extends [[canon-memory-architecture-claude-obsidian-hermes]].

THE WHY (the real driver — qi's words): he services 300+ clients across multiple enterprises and his agent forgets scopes, tools, auths, server ports, and canon between sessions. Without verbatim logs it "can't truly return to regularly scheduled programming" without him — leading to months of rebuilding what already worked from scratch, and "fighting insanity and insomnia from pure distrust and hatred of repeating months of prompts and mandates I was sure it learned." Root cause: no persistent ground truth — qi is the sole carrier of all context in his head + fragile chat history. FIX = externalize everything the agent needs to be itself.

1. AUTH BRIDGE — qi's MOST IMPORTANT PIECE ("Let's get great at that skill"). Use his ALREADY-LOGGED-IN Claude Code session as the model backend for other tools (BrowserOS, OpenClaw, dispatch) — NOT a separate API key, NOT Ollama, NOT a different model.

  • VERIFIED REAL methods (the doc fact-checked itself — claude --serve and claude setup-token are HALLUCINATED, do NOT exist; real CLI auth surface = claude auth login|logout|status):
  • macOS Keychain extraction (qi's default, on M4): security find-generic-password -s "Claude Code-credentials" -w → JSON claudeAiOauth.accessToken (starts sk-ant-oauth..., expires ~8h) + refreshToken (indefinite). Shell fn get_claude_token() → export ANTHROPIC_AUTH_TOKEN=$(...), ANTHROPIC_BASE_URL=https://api.anthropic.com. Cron every 7h → write to a shared ~/.xen/current_token.txt; ALL tools read that one live token.
  • mitmproxy intercept (route all Claude traffic through a local proxy; tools hit the proxy). qi's files already documented this months ago.
  • ai-cc-router (npm) — round-robins OAuth tokens across multiple Team seats, writes ANTHROPIC_BASE_URL/AUTH_TOKEN into settings.json. Multi-seat = multiplies usage budget.
  • NITRO NUANCE (Design B): the brain runs on Nitro/Windows now, not Mac. Keychain extraction is macOS-only. On Nitro the Claude creds live in E:\.claude\.credentials.json (or Windows Credential Manager) — adapt the extraction per-OS. VERIFY the real cred path on Nitro before building.

2. CANON FILE SYSTEM (the resume spine). ~/.xen/canon/ (git repo, append-only, committed every state change):

  • GLOBAL.md (East's identity, comms rules, master mandates), enterprises/.md, clients/.md (300+: scope, creds-ref, active work, last state), agents/xen-main.md (tools, MCP servers, ports, auth tokens, capabilities), LAST_KNOWN_STATE.md (active enterprises, in-flight client work, running services+ports, tools/auths, "what was happening when I stopped", "what was next" — verbatim, not summarized).
  • CLAUDE.md = agent DNA: BEFORE every task read GLOBAL + LAST_KNOWN_STATE + relevant enterprise/client canon + agents/xen-main. AFTER every task update LAST_KNOWN_STATE + client canon + write session chunk. NON-NEGOTIABLE: never ask East to re-explain setup/tools/clients — it's in the files; if a file is missing, SAY SO, don't hallucinate. Shutdown hook auto-commits state. Cold-start = cat 3 files → full restoration, zero re-prompting.

3. VERBATIM SESSION CAPTURE (lossless — qi: "Don't remove anything. Chunk instead"). Every shell session captured in FULL (commands + all output), never summarized/truncated: kautolog/script (TTY) + Atuin (commands+metadata, SQLite FTS) → fswatch daemon ships chunks to Elasticsearch xen-sessions-verbatim (overlapping windows, ~2000 char / 200 overlap so nothing falls between chunks). Hermes queries it before tasks; prefer verbatim logs over summarized memory.

4. UNIFIED MEMORY SPINE. working=mem0 · long-term semantic=Elasticsearch xen-brain (hybrid BM25+vector RRF) · deep synthesis=NotebookLM (CPR: Compress→Preserve→Resume) · fast KV/locks/pubsub=Redis · canon/knowledge-graph=Obsidian via MCP. One MCP block (memory/obsidian/elasticsearch/notebooklm) in settings.json → inherited by every dispatched agent. Write-path after each session → read-path before each task.

5. HERMES = autonomous curator over the spine: bounded persistent memory (MEMORY.md ~2200 chars / USER.md ~1375, frozen-snapshot at session start, memory tool add/replace/remove, write_approval:false=write freely), background self-improvement review after each turn (can run on a cheaper model), session_search FTS5 over ALL past sessions (unlimited, ~20ms, no LLM cost), 8 external providers (mem0/Supermemory/etc). Hermes = brain; OpenClaw = execution/channels (voice/Telegram/Discord/Slack/iMessage/WhatsApp gateway @127.0.0.1:18789) — two halves, glued via MCP (Hermes calls OpenClaw as a tool, absorbs output). OpenClaw stuck at model picker → unblock via the auth-bridge (point it at the logged-in Claude session) NOT Ollama.

6. SCOPE REGISTRY + ROUTING (qi's build order). FIRST build a master scope registry (cols: scope_id, enterprise, client, objective, systems, auths, ports, canon_files, status, urgency, dependencies, execution_policy = single|parallel|hold). DON'T explode everything into threads. Thread ONLY the parallel set (one thread per BOUNDED scope w/ clean seams; each has scope.md + append-only state.log + routing key). New inbound work resolves against registry FIRST → append to existing thread, else spawn only if independent + measurable. Over-threading = context rot.

7. ALIAS ROUTING (voice-first). Aliases are STABLE routing handles → registry lookup → active thread (NEVER hardcode raw thread IDs — they drift). 10–30 high-value aliases only. Voice synonyms first-class (dictation varies: "client forty two"/"c042"/"forty-two" → same key). Schema: alias, canonical_scope, allowed_actions, default_thread_policy (append|resume-latest|spawn-if-none), synonyms, priority_override. Normalize synonyms → resolve scope → route; clarify only on low confidence.

STATUS: captured/injected.
