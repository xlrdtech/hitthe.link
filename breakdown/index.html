Xen · session breakdown · 2026-08-23 · 02:00–04:30 EDT

Every defect had a green light on top of it.

Seven real failures found in one night across xlrd.life, three deploy platforms and the goal swarm. Not one of them showed up as an error. Every single one passed a status check and failed a content check.

A status code describes the transport. It never describes whether the thing works. 301 on a dead link. 200 serving the wrong page. display:standalone set correctly next to a start_url that 404s. A timeout counter climbing while the failure counter sits at zero. The check being green is not evidence.

Nine false zeros

Separately, nine times a number described my own instrument instead of the world. Each would have produced a confident wrong answer alone.

  1. ls -1 on a directory of dotfiles → 0. Real answer 6. Nearly reported deleting six files.
  2. pgrep -fl counting lines, not processes — each worker's argv holds a multi-line prompt. 445 vs 3.
  3. Python len() counting characters where wc -c counts bytes. 47,651 vs 48,170.
  4. An upload log's last flushed line read as progress — said 285/3298, server had taken 3,297.
  5. A screenshot served from browser cache while curl already had the new bytes. The image was the stale artifact.
  6. curl -L not following a meta-refresh redirect — "didn't redirect" where a browser does.
  7. A 400 "Invalid request headers" beside a credential read, which looks exactly like a dead key. The key was fine; a label was being sent as an email.
  8. A per-file size cap rejecting a deploy while 200 came back for the excluded path — an SPA fallback wearing the right status code.
  9. A build list whose top row said "errored" and second row, one second later, said "built". Reading only the latest would have reported a failure that had already healed.

Four decisions · not mine to make

The goal swarm

One redirect on the worker-spawn line. Not applied unilaterally: that file is load-bearing and was mid-flight with live workers — a bad edit stops the swarm outright instead of merely stalling it. Until then it burns three workers per ten-minute cycle producing nothing.

claude -p "$PROMPT" < /dev/null

The third platform

Genuinely no credential present — measured four independent ways, all negative. Needs a login run in-session, a token, or an OAuth approval. Completing an OAuth consent grants an app access to an account, which is a decision for a person, not something to drive a browser through.

The stale project

No deployment since a failed build in May 2025, despite pushes through November. Revive the git connection or retire it deliberately — it may already be abandoned on purpose, which is why it was left alone.

What is public

A clone carries whatever the source carried. Deploying the same tree to a second platform doubles the exposure surface of anything in it that was never meant to be published. Worth an explicit pass rather than an accident of cloning.
