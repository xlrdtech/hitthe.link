01 The convergence

Four independent sources, one blueprint

None of these people were talking to each other. A founder interview about running a business on agents. A beginner coding stream. A spec-driven build walkthrough. A review of an enterprise agent platform with $27M behind it. Every one of them landed on the same four requirements.

02 The number that should end the debate

“Within two weeks we replaced the entire role”

“I hired someone for two or three thousand dollars a month. Within two weeks we essentially replaced the entire role with an AI agent. And in fact the output was even better quality, because it was all automatable.”
— founder interview, 08:41

He put the time saving at “well over 20 hours” a week and then corrected himself: the real impact is higher, because it isn't only hours. It changes what you're willing to attempt. His example was asking an agent to audit an entire X account and return a 30-day plan — work nobody would commission at consultant rates for a maybe.

The framing worth stealing: an agent isn't a faster tool, it's a lower threshold. Tasks that were never worth starting become worth starting.

04 The contradiction nobody flagged

Enterprise logos, alpha repo

The product review spent three minutes establishing credibility — an open protocol adopted by Google, Microsoft, Amazon and Oracle; $27M Series A; Deutsche Telekom, DocuSign, Cisco and S&P Global in production. Then, almost in passing:

“The commit history is short, and right there in the readme the team labels it clearly as Alpha and under active development. They're telling you up front to expect rough edges, expect bugs.”
— product review, 14:46

Both things are true at once, and the gap between them is the actual story. The protocol is adopted. The product is weeks old. Enterprise logos attach to the standard, not the app — and a reviewer who leads with the logos and buries the alpha label has inverted the weight.

Reusable frame: ask which layer the credibility belongs to. Protocol adoption and product maturity are different claims wearing one badge.

05 Craft notes worth keeping

From the spec-driven build stream

  • One feature per session. Never combine unrelated system boundaries in a single implementation step — that one rule prevents most agent failures.
  • Out-of-scope is doing the real work. Listing what you're not building keeps every session pointed at what you are.
  • Name the tools up front so the agent doesn't invent a custom websocket layer when a real one is already in the stack.
  • Success criteria as checkable statements — not “build a canvas” but “an authenticated user can create and open a project.”
  • A progress file is the memory. It's the smallest file in the repo and does more work than any other, because the agent reads it and knows exactly where things stand.

From the beginner stream — the one line that transfers

“If you have an aim and you hit an error, you'll try to solve it. Without one you just stop.”
— coding livestream, 12:52

Aimed at first-time coders, but it is the whole argument for scope files. A goal is what converts an error from a reason to quit into a step.
